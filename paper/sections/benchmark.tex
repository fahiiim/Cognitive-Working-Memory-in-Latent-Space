\section{The DepthShift benchmark}
\label{sec:benchmark}

DepthShift pairs tasks that have an exact per-instance depth oracle with a split design that
separates \emph{longer} inputs from \emph{deeper} ones (\cref{fig:splits}). All generators run on the
GPU from fixed seeds; test sets are frozen and stored with SHA-256 hashes, and the training sampler
drops any instance whose hash matches an in-distribution validation or test instance.

\paragraph{T1: addition.} Two $L$-digit numbers, least-significant digit first, one token
$10a_i+b_i$ per position, plus one position for the final carry. By \cref{prop:oracles}, $d^*$ is
the longest run of digit pairs summing to~9, plus one. To control $d^*$ independently of $L$, the
generator inserts exactly one run of length $d^*-1$ between two stops, draws background runs with
a random density, and caps them below $d^*-1$. Stops are uniform over the 90 pairs with $a+b\ne 9$,
so a run receives a carry with probability $1/2$.

\paragraph{T2: segmented parity.} Bits with delimiter tokens; the output at each position is the
parity of the current segment so far. $d^*$ is the longest segment. Unlike addition, intermediate
outputs keep flipping as information arrives, so the per-step predictions do not settle early.

\paragraph{T3: mazes.} $n\times n$ mazes from a randomized depth-first generator (input channels:
open cell, start, goal; output: the shortest path). Information travels along corridors, so the light
cone gives only a loose bound. We record two empirical depth proxies: the optimal path length and
the number of dead-end-filling iterations a local rule needs to isolate the path.

\paragraph{Splits.} For T1 and T2 (\cref{tab:splits}): in-distribution (ID) lengths 4--20 and depths
1--10; OOD-depth keeps the lengths but uses depths 11--20; OOD-length uses lengths 64--256 at ID
depths; OOD-both uses lengths 64--256 and depths 32--128, up to $12.8\times$ the training maximum.
A separate OOD-validation split (lengths 24--32, depths 12--16) is used only to tune the backbone.
Thresholds of every stopping rule are chosen on ID-validation. For mazes we train on $9\times 9$ and
test on $13\times13$ to $33\times33$.
